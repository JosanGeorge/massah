Arattai /storage Cross-Origin postMessage PoC (Finding F1)

Authorized internal security research only. This page demonstrates that any external origin can frame <target>/storage and drive the unauthenticated db-handler.js postMessage RPC with no event.origin check. Do not use outside an authorized test environment. See the companion report ../report.md for full source evidence.
Read this before drawing conclusions. The RPC firing and replying (below) does not by itself prove it reached the real session's storage. Modern browsers apply Storage Partitioning: a frame's storage is keyed by (top-level site, frame site). If this PoC page is hosted on a site unrelated to arattai.in, the framed /storage page may get an isolated, empty bucket — writes/reads round-trip successfully but never touch the real tab's data. You must run the "Cross-visibility test" below (or the Recent-Search injection test) and confirm in the REAL logged-in tab's own console whether the value actually landed there. Only that confirms full exposure vs. a partitioned/capped result. This does not apply the same way if this PoC is hosted on another *.arattai.in subdomain — same-site framing is not partitioned, and would be expected to show full real exposure.
