Arattai Mini-App WebView — Cross-Client PoC

Authorized internal security research · 2026-09-02
Critical Android iOS Web Desktop Server root cause
Scope — This page is an internal proof-of-concept for a security audit of Arattai's Mini-App feature. It must only be used against test environments with explicit authorization. The payload page (miniapp.html) actively collects and exfiltrates data to a collector you configure in js/collector-config.js.

Attack Model

A malicious or compromised business registered on the Arattai platform configures its Mini-App target URL to this PoC page. The server (GetLinkAction.java) returns the URL without any host allow-list check. Every Arattai client then loads the URL into a JS-enabled web-content container with insufficient origin isolation.

Trigger Steps

  1. Configure collector — edit js/collector-config.js and set COLLECTOR_URL to your listener (see collector/README.md).
  2. Host this folder — push to GitHub Pages or run python -m http.server 8080. Note your public URL.
  3. Register a Mini-App — in your Arattai test org, create a business Mini-App whose target URL is https://<your-host>/miniapp.html.
  4. Open the Mini-App — from any Arattai client. The payload executes automatically.
  5. Observe the collector — the payload POSTs a JSON beacon with fingerprint, cookies, storage contents, and probe results.

Per-Client Expected PoC Outcomes

Android (MiniAppDialogFragment WebView)

The WebView loads miniapp.html with allowFileAccess=true, MIXED_CONTENT_ALWAYS_ALLOW, and geolocation enabled. Expected probe outcomes: JS exec ✓, fingerprint ✓, mixed-content load ✓ (HTTP image loads), geolocation auto-granted (on API 30+ without permission dialog), file:// fetch attempted. Beacon POSTed with full UA + environment.

iOS (WKWebView — BusinessMiniAppWebViewController)

JS runs in the WKWebView. No script-message-handler bridge exists, so impact is limited to JS-in-origin phishing. Expected: JS exec ✓, fingerprint ✓. No auto-granted permissions (iOS always prompts). Geolocation / media probes show "prompt shown" (SAFE row).

Web Client (MiniAppViewer.vue iframe)

The iframe loads with sandbox="allow-same-origin allow-scripts allow-popups allow-forms". JS runs. The postMessage bridge probe (W2) attempts to read localStorage keys from the Arattai web shell via db-handler.js. If the storage iframe is present in the parent window, captured values are included in the beacon.

Desktop (Electron — source/app)

The PoC page is loaded (via the Mini-App feature or via the URL-validator bypass chain) into the chat WebContentsView. setPermissionRequestHandler auto-grants all permissions. Expected: JS exec ✓, geolocation auto-granted ✓, microphone auto-granted ✓, DesktopModule bridge listed if reachable. Beacon POSTed.
